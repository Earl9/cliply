## 1. 文档目的

本文档汇总 Cliply 本轮优化过程中已经确认的产品方向、界面规范、安装程序要求、同步数据治理、性能目标与发布标准，作为后续实现、评审和回归测试的统一依据。

详细性能数据、代码热点与专项测试方法见 [性能优化方案](performance-optimization.md)。本文件负责统一目标与验收口径，不替代各专项技术文档。

## 2. 产品定位

Cliply 是一款面向 Windows 的本地优先剪贴板工具。界面应像成熟、克制的桌面效率软件，而不是网页仪表盘、营销落地页或 AI 助手。

核心体验目标：

- 打开后可以立即搜索、浏览、选择和粘贴；
- 信息密度适中，减少无意义留白，但不牺牲可读性；
- 界面现代、年轻、有颜色，但不依赖渐变、发光和装饰性图形；
- 主程序、图标、安装程序和文案使用同一套品牌语言；
- 本地数据、同步数据和删除记录的处理规则清晰、可解释、可恢复；
- 长期后台运行时保持低 CPU、低磁盘写入和稳定内存占用。

## 3. 不可变更的设计与产品约束

### 3.1 界面结构

- 不使用侧边栏；
- 不增加 Hero、宣传口号、页面大标题或外层仪表盘卡片；
- 主界面保持紧凑的原生标题栏、搜索工具行、双栏工作区和底部状态栏；
- 历史列表与详情始终是主工作流，不用装饰性模块分散注意力；
- 最小窗口 `860 × 560` 和高 DPI 环境下必须保持主要功能可用。

### 3.2 视觉方向

- 使用 Open Design 方案作为设计来源；
- 当前 Open Design 项目：`cliply-modern-20260811`；
- 对应产物：`cliply-modern.html`；
- 仓库镜像：`designs/cliply-modern-open-design.html`；
- 保留 Windows Acrylic，并在 WebView 内建立有层级的半透明玻璃材质；
- 主题年轻、多彩但克制，主色只承担主要操作、选中、焦点和固定状态；
- 禁止用渐变、光晕、星光、机器人、魔法棒等常见 AI 视觉符号。

### 3.3 数据与同步

- 不改变本地优先原则；
- 不改变现有冲突合并、同步队列和墓碑语义；
- 未完成同步的删除记录不能直接物理删除；
- 不以缩短历史记录上限代替列表性能优化；
- 日志和诊断不得记录剪贴板正文、密码、令牌或加密载荷。

## 5. 主界面重构规范

### 5.1 页面骨架

主窗口采用无侧边栏的双栏工作台：

1. 紧凑标题栏；
2. 高度约 52 px 的搜索与结果统计行；
3. 左侧历史列表；
4. 右侧详情预览；
5. 底部状态栏。

布局要求：

- 历史列表宽度在约 280–344 px 范围内流动，占可用宽度约三分之一；
- 详情区使用剩余空间，并允许内容真正收缩；
- 工作区、详情区、滚动视口和操作栏均设置正确的 `min-width: 0`；
- 长代码、长链接和大图只能在自己的预览区域内滚动，不能撑宽窗口；
- 列表工具栏与详情标题栏高度统一为约 48 px；
- 搜索、筛选、列表、详情和底部操作之间保持明确但不过度的层级。

### 5.2 高度与留白

- 减少标题、工具栏、预览区和底部操作区之间无功能的大块空白；
- 空状态、加载状态和完成状态不能只保留一个居中的图标和大面积空白；
- 详情内容应根据窗口高度自动分配，主要预览优先获得空间；
- 底部主要操作在最小高度下仍保持可见；
- 采用 8 px 间距节奏，必要时使用 4 px 光学校正；
- 不通过堆叠卡片或增加装饰模块填充空白。

### 5.3 响应式与高 DPI

- 在 `860 × 560` 最小窗口下，历史列表、详情和主要粘贴操作同时可见；
- 详情容器低于 600 px 时，内容边距收缩到约 16 px；
- 详情容器低于 680 px 时，次要操作可收敛为带工具提示的图标按钮；
- “粘贴”始终保留完整文字，不与次要操作一起隐藏；
- 筛选标签在窄宽度下保持单行，可在工具栏内部横向滚动；
- 125%、150%、175% 和 200% Windows 缩放下不得出现裁切、重叠或按钮不可达；
- 窗口缩放期间不应出现明显布局跳动。

## 6. 颜色与毛玻璃系统

### 6.1 颜色角色

默认主题使用年轻但专业的珊瑚色与薄荷色组合：

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| 主强调色 | `#FF6257` | 粘贴、选中、焦点、固定状态 |
| 悬停色 | `#FF7066` | 主操作悬停 |
| 按下色 | `#F75A50` | 主操作按下 |
| 成功/本地状态 | `#168F73` | 浅色主题成功与保留状态 |
| 深色成功色 | `#3DD0AC` | 深色主题成功与保留状态 |
| 主文字 | 中性石墨色 | 正文与标题 |
| 次要文字 | 中性灰 | 时间、格式、辅助说明 |

使用规则：

- 强调色只用于具有明确交互或状态意义的元素；
- 不使用深色横条或突然加深的色块划分普通内容；
- 内容类型通过图标形状和文字说明区分，不为每种类型分配高饱和颜色；
- 薄荷色表示本地、安全保留、同步完成或成功，不与主按钮争夺注意力；
- 禁止紫蓝渐变、霓虹边缘、彩色发光和大面积品牌色蒙层。

### 6.2 毛玻璃层级

Windows Acrylic 是主模糊层。WebView 内使用半透明背景、细边框和轻阴影建立玻璃层级。

- 整窗和大面板不重复叠加多层 `backdrop-filter`；
- 大面积结构层最多保留一层模糊；
- 菜单、对话框、浮层等小面积区域可保留 CSS 模糊；
- 每个半透明表面必须有细微高光边缘和实体背景降级方案；
- 浅色模式避免脏灰，深色模式避免整片纯黑；
- `prefers-reduced-transparency` 和高对比度模式下关闭所有 CSS 模糊；
- 不为大面积模糊表面添加动画。

建议材质权重：

- 窗口背景：约 34%；
- 标题栏和工具栏：约 58–68%；
- 主面板：约 36–48%；
- 内容面板：约 60%；
- 输入框和按钮：约 76%；
- 深色模式使用更高的不透明度保证文字清晰。

## 7. 组件与交互细节

### 7.1 搜索与筛选

- 搜索框高度约 40 px，保留完整键盘操作面积；
- 结果数量放在搜索行末端，不额外占用一整行；
- 筛选使用紧凑分段控件，仅当前项有明显抬升；
- 焦点环清晰但克制，不能使用强发光；
- 搜索输入不能导致整个页面无差别重渲染。

### 7.2 历史列表

- 单行视觉高度约 68 px，行间节距保持紧凑；
- 选中状态使用轻量强调色底、细边框和短侧边标记；
- 图标放在中性边框容器中，不使用彩色图标底板；
- 时间、来源和类型信息使用统一的次要文字层级；
- 固定、删除、右键菜单和双击粘贴行为不变；
- 500–1,000 条记录时使用虚拟化，DOM 只保留可视行和少量 overscan。

### 7.3 详情区域

- 详情只保留“内容预览”和“记录信息”两个主要功能面板；
- 文本、代码、链接和图片使用一致的容器边界；
- 元数据使用易扫描的双列定义布局；
- 来源窗口可跨整行显示；
- 标签使用紧凑中性样式；
- 次要操作置左，主要“粘贴”置右；
- 仅主要粘贴操作使用实心强调色。

### 7.4 状态与反馈

- 加载、空状态、错误、禁用、悬停、焦点和完成状态必须齐全；
- Toast、对话框和状态切换反馈控制在 200 ms 内；
- 尊重 `prefers-reduced-motion`；
- 不对应用外壳、双栏布局和大面积玻璃层做进入动画。

## 8. 图标与品牌资产

### 8.1 应用图标

Cliply 图标采用双纸片符号：

- 珊瑚色表示当前剪贴内容；
- 薄荷色表示历史与保留；
- 使用暖白折角和石墨色内容线；
- 不使用传统剪贴板轮廓、蓝色文档堆、字母标志、渐变、星光或 AI 吉祥物。

小尺寸图标不能直接缩小大图：

- 16–48 px 使用光学校正版本；
- 可见图形约占画布 88–92%；
- 保证任务栏、开始菜单和资源管理器中与其他软件视觉尺寸接近；
- 图形不能贴边或在低 DPI 下糊成一团。

### 8.2 全链路统一

以下位置必须使用同一套图标来源和品牌规则：

- 主程序窗口和任务栏；
- 系统托盘；
- 主程序可执行文件；
- 现代安装程序窗口；
- NSIS 备用安装程序；
- 安装程序头图、侧图和 Logo；
- 开始菜单、桌面快捷方式和卸载项；
- README 截图与发布页面。

界面功能图标统一使用同一线性图标库和一致线宽，避免混用 Emoji、实心符号和不同风格 SVG。

## 9. 文案优化规范

界面与安装程序文案应正式、直接、可核验。

### 9.1 推荐表达

- 使用“安装”“更新”“同步”“保存”“删除”“重试”等标准桌面术语；
- 状态文字说明当前结果或下一步操作；
- 数据保留和安全说明只陈述真实行为；
- 错误信息包括问题、影响和可执行的解决方式；
- 同一屏幕不重复承诺“安全”“放心”“不会丢失”。

### 9.2 禁止表达

- 宣传口号、拟人化语气和反问句；
- “智能整理”“为你守护”“轻松开启”“焕新体验”等空泛措辞；
- 把普通功能描述成魔法或 AI 能力；
- 大段解释用户显然已经看到的界面内容；
- 为追求亲切而牺牲准确性的口语化提示。

### 9.3 文案验收

- 主程序、设置、更新、同步、安装、卸载和错误提示统一审校；
- 所有按钮使用动作词；
- 所有状态文本在脱离插图后仍能独立理解；
- 中英文术语在 README、安装程序和应用内保持一致。

## 10. 安装程序优化

### 10.1 现代安装程序

独立现代安装程序是主发布产物，NSIS 仅作为备用安装和恢复方案。

界面要求：

- 固定逻辑尺寸约 `720 × 480`；
- 44 px 紧凑可拖动标题栏；
- 使用与主程序一致的 Acrylic、颜色、字体和图标；
- 安装与更新页面只保留产品说明、功能设置面板和底部操作栏三层；
- 安装路径、更新状态、数据保留、快捷方式和开机启动选项集中在功能面板；
- 处理中与完成状态复用相同布局，不切换成空旷的居中启动页；
- 进度显示真实百分比、当前步骤和明确的数据保留状态；
- 安装、更新、卸载、错误和完成状态在高 DPI 下均不能裁切主要按钮。

### 10.2 安装行为

- 支持默认路径和自定义路径；
- 安装或更新前尝试关闭正在运行的 Cliply；
- 更新覆盖程序文件但保留用户数据；
- 正确创建和移除开始菜单、桌面快捷方式及开机启动项；
- 卸载默认保留用户数据，只有用户明确选择时才删除；
- 更新包下载后必须校验 SHA256；
- 失败时提供日志位置和 GitHub Release 手动下载入口；
- 安装、更新和卸载过程中不显示多余控制台窗口。

### 10.3 发布产物

每次正式构建至少输出：

```text
release-assets\Cliply_<version>_x64-modern-installer.exe
src-tauri\target\release\bundle\nsis\Cliply_<version>_x64-setup.exe
```

现代安装程序必须作为可单独运行、可直接交付用户的完整安装包。发布前记录 SHA256，并检查签名状态。

## 11. 同步队列与墓碑清理

### 11.1 为什么不能立即删除

已删除记录需要先保留为同步墓碑，用于通知其他设备同一条记录已经删除。如果本地立即物理删除，其他设备可能在下一次同步时把旧记录重新带回，或者永远无法获知删除操作。

因此，删除流程应分为：

1. 用户删除记录；
2. 本地记录标记为已删除并生成墓碑；
3. 删除事件进入同步队列；
4. 墓碑进入完整同步快照；
5. 同步成功并经过保留期；
6. 后台清理服务物理删除墓碑及其关联数据。

### 11.2 允许物理删除的条件

只有同时满足以下条件，才允许硬删除：

- 删除状态已进入可恢复的同步快照；
- 对应同步事件已完成处理，不再需要重试；
- 已超过配置的墓碑保留期；
- 清理不会破坏本地固定记录保护和冲突合并规则；
- 关联的格式、标签、图片元数据和 Blob 可以在同一事务中安全清理。

未同步、待重试或仍承担冲突保护作用的墓碑不能直接删除。`abandoned` 事件本身可停止重复上传，但对应墓碑基线仍需要进入完整快照，防止远端旧数据复活。

### 11.3 队列治理目标

- 合并重复的未同步事件；
- 对永久失败或已被新事件取代的队列项进行明确归档；
- 同步完成后正确标记 Checkpoint；
- 定期清理已同步且超过保留期的墓碑；
- 批量删除关联数据，避免逐条 SQL 和大量小事务；
- 清理过程可中断、可重试，不阻塞主界面；
- 诊断页面分别显示有效记录、墓碑、未同步事件和可清理数量；
- 用户触发的“清理”只能清理满足安全条件的数据。

### 11.4 数据治理验收

- 删除记录不会在其他设备重新出现；
- 未同步墓碑不会被误删；
- 清理后同步包语义保持一致；
- 清理任务失败不会造成半删除；
- 数据库大小和队列数量在完成同步与保留期后可下降；
- 真实用户数据库只做只读审计，压力测试使用独立测试数据库。

## 12. 性能与磁盘寿命优化

### 12.1 当前基线摘要

基线日期 2026-08-14：

| 指标 | 结果 |
| --- | ---: |
| 工作集内存 | 约 52 MB |
| 私有内存 | 约 20 MB |
| 10 秒空闲 CPU | 约 0–0.31% 单核 |
| 10 秒空闲磁盘读取 | 0 B |
| 10 秒空闲磁盘写入 | 0 B |
| 数据库大小 | 17,473,536 B |
| 有效记录 | 249 |
| 墓碑 | 2,217 |
| 未同步事件 | 4,497 |

当前未发现软件空闲时持续读写硬盘的问题。后续优化重点是避免高频唤醒、重复全量查询、小事务写入和高频日志，而不是通过频繁 `VACUUM` 制造额外写放大。

### 12.2 前端热路径

- 历史列表使用固定高度虚拟化；
- 列表行使用稳定 key、稳定事件函数和渲染隔离；
- 搜索输入不重渲染所有未变化记录；
- 键盘选择后自动滚动到可视区域；
- 剪贴板新增和单项修改使用增量事件，不每次完整查询列表；
- 自定义滚动条使用 `requestAnimationFrame` 合并滚动更新；
- 收敛大面积 CSS 模糊，降低滚动与缩放时的 GPU 合成成本。

### 12.3 后台、同步与数据库

- 同步导出按 ID 分块批量读取格式和标签，消除 `2N` 查询；
- 自动同步调度器使用可唤醒等待，不每 250 ms 轮询；
- 保留初始延迟、同步周期和指数退避语义；
- `PRAGMA optimize` 只在迁移或低频维护点执行；
- 不增加重复索引，不高频执行 `VACUUM`；
- 日志使用轮转、限量和错误去重；
- 设置、关于和更新等冷路径按需加载。

### 12.4 性能验收

- 1,000 条记录时列表 DOM 仅包含可视行与 overscan；
- 60 Hz 屏幕连续滚动目标平均帧率不低于 55 FPS；
- 普通复制后不执行完整 `list_clipboard_items`；
- 从复制到列表可见 P95 目标低于 100 ms；
- 2,500 个同步项目的数据库准备阶段目标低于 60 ms；
- 同步导出查询数不再按 `2N` 增长；
- 30 分钟空闲采样无持续磁盘写入；
- CPU、内存和线程数量不高于当前基线的合理波动范围。

7. 1,000 条记录压力测试、同步大队列测试和 30 分钟空闲测试通过；
8. 空闲状态无持续磁盘写入，不存在明显写放大；
9. TypeScript、生产构建、Rust 测试和安装包构建全部通过；
